# Proposal: Drive legacy gate debt down with verified remedies

## Why

`QUALITY_NEW_CHANGE_WITH_GATE_DEBT` prevents new work from opening while required gate commands are unbound. A blocking rule needs a repair path for mechanical debt; otherwise repositories can remain stalled indefinitely. The measured baseline is 24 unresolved entries classified A=10, B=7, C=3, D=2, E=1, F=1, with no unclassified reasons.

## What Changes

Add one governance-owned driver that reads the recorded debt reasons, classifies them into six explicit classes, previews by default, and applies only verified mechanical remedies. Classes A-D are repairable. Classes E-F and unknown classes are escalated with their evidence and are never guessed. Repositories are re-measured after remedies; the debt record remains generated by the existing binder.

The driver owns five shared checker implementations in `workspace-governance/scripts/check_concern.py`; product repositories receive only thin `scripts/check-<concern>.py` entry points. Class B creates or completes a solution with every discovered project. Class C declares a Python build backend and relies on the binder to derive the build command only when its build requirements are satisfiable. Class D declares `pip-audit` and runs it, reporting network/tool failures without misrepresenting them as passes.

## Package Boundary and Split Assessment

This package has one owner and one acceptance boundary: `/home/paul/code/workspace-governance`, Python 3, with a driver that applies a mechanically justified remedy to a debt entry and leaves unresolved decisions visible. The affected product repositories are write targets only for explicit `--apply`; their gate implementations and product behavior are outside this package. The separately deployable concerns of making Driftwatchdog schedule governance for all profiles, changing new-project scaffolding, and enforcing a live debt ratchet are excluded and require dependency-ordered OpenSpec changes in their owning repositories.

The split signals are distinct runtimes, owners, and acceptance oracles: driver behavior is measured against debt entries; mandatory scheduling is measured by Driftwatchdog plans; scaffolding by generated manifests; and the ratchet by a preflight integration test. Therefore this is the smallest coherent package for the existing debt-driver work.

## Sibling and Shared Architecture Reconnaissance

| Candidate | Evidence path/symbol | Reusable code/config/architecture | Compatibility gap | Owner and release boundary | Decision |
|---|---|---|---|---|---|
| Driftwatchdog | `driftwatchdog/src/gate/manifest.rs`, `gate-debt.json` | Gate execution, concern selection, and debt output | Runtime should consume commands, not own Python checker implementations or cross-repository repair writes | Driftwatchdog owns gate execution and releases independently | adapt through a generic adapter |
| Forge | workspace project registry and `forge` command surfaces | Portfolio orchestration and project catalog | Does not own deterministic filesystem diagnosis or checker logic | Forge owns orchestration/release | keep local |
| Shared platform contracts | `platform-contracts` schemas | Versioned cross-language contracts | Driver is local Python maintenance tooling and has no runtime wire contract to publish | platform-contracts owns reusable schemas | keep local |

The checker engine is repeated across repositories but remains owned centrally by `workspace-governance`; product shims depend on its workspace-relative location, and no checker implementation is copied. Driftwatchdog remains the gate oracle. No sibling source edits are required by this package beyond explicitly applying the driver's generated repairs.

## BFS Impact Map

- **Users and flow:** maintainers run a dry report, review class and evidence, then explicitly run `--apply`; the binder regenerates commands/debt afterwards.
- **State and persistence:** input is the existing governance-root `gate-debt.json`; output is JSON/text reporting and project-local checker, solution, packaging, or dev-dependency files. No new persistent debt format is introduced.
- **Integrations:** `dotnet` solution commands, Python packaging metadata, `pip-audit`, the shared checker engine, and `bind_gate_commands.py`.
- **Failure and boundaries:** malformed debt entries are ignored only when required identity fields are absent and reported in diagnostics; unknown reasons are escalated, filesystem/read errors fail the affected remedy, command output is checked in addition to exit status, and no command failure is reported as a successful verification.
- **Security/privacy:** no secrets are read or emitted; checker output names repository-relative file and line; generated shims do not copy checker logic.
- **Compatibility:** driver defaults to dry-run and retains the existing debt schema. `--apply` is the only write switch. Existing operator commands are not overwritten.
- **Verification:** unit tests pin each classifier, negative unknown/decision controls, idempotent solution handling, generated checker behavior, and class-C binding eligibility; real workspace measurement checks all 24 entries and reports actual findings after binding.
- **Unaffected:** deployment, registry declarations, platform adoption, and product documentation remain unchanged.
