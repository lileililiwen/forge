# UI Kit Adoption — the repeatable mechanism

One rule for two populations: **new projects are born compliant; legacy projects
drain the ratchet.** Do not invent a parallel mechanism — everything below is
already built and proven in 20+ repositories.

## Sources of truth (never copy, always point)

- Kit: `dotnet-platform-libs/ui/` — `tokens.json` (DTCG) → `scripts/generate-tokens.mjs` →
  `packages/design-tokens/dist/tokens.css`. Consume the built artifact, never hand-edit it.
- Current fleet pin (kit 0.2.0): `tokens.css` sha256
  `7ca6b7956b3f6b475254b4a5d0cf599724e4e1af5f0f88aba4fbccb9f38fc19b`;
  npm tarball `@platform/design-tokens-0.2.0.tgz` sha256
  `e48284cbc105cd6ded61b2d6320cc38d109a5f0306d565e4f9c1b07dd91cbc8c`.
  On a kit version bump, refresh these pins here, in `forge/kits/manifest.json`, and in every
  consumer drift-guard test in the same fleet sweep.
- Governance: `workspace-governance/scripts/ui_conformance.py` (the checker),
  `scripts/bind_ui_gate.py` (the binder, `--check`/`--apply`), `docs/ui-convention.md`
  (the `.project.json` `ui` block shape), `ui-conformance-baseline.json` (the ratchet —
  generated by `scripts/generate_ui_conformance_baseline.py`, never hand-written).
- Ruling D18: a verifier that no gate runs does not gate. Declared silence (no
  `ui.scope.roots`) is not a pass.

## Population 1 — new projects: compliance by construction

When bootstrapping any repo with a UI surface, provision before the first feature commit:

1. Vendor `tokens.css` byte-identical into the app source tree; verify the sha.
2. Declare the `ui` block in `.project.json` (scope.roots, consume_paths, pin_sha256,
   branding_document, contrast_evidence) — see `docs/ui-convention.md`.
3. Bind the gate: `.ai-gate/gate.yaml` in rule_pack `workspace-governance@1` shape, then
   `bind_ui_gate.py <repo> --apply`, with `timeouts:` sized for the stack.

A new project gets **no baseline entry**: any `UI_*` finding is a real failure to fix now,
not a grandfathered state. When regenerating the ratchet, confirm newly registered
projects did not acquire entries; if one did, treat it as debt against that repo, not an
exemption. `new-project-bootstrap-workflow` routes here for the UI shell.

## Population 2 — legacy projects: the baseline IS the backlog

`ui-conformance-baseline.json` lists every grandfathered project with codes and counts.
Drain it, don't re-audit the fleet each time:

```sh
# stale entries = adoptions that landed (the ratchet must shrink)
python3 workspace-governance/scripts/generate_ui_conformance_baseline.py --root . --check
# after a wave, regenerate; prove shrink-only (no new projects, no grown counts)
python3 workspace-governance/scripts/generate_ui_conformance_baseline.py --root . --out /tmp/new.json
python3 scripts/generate_ui_conformance_baseline.py --root . --out - | python3 -c "import json,sys; ..."  # or diff by project/codes
```

Prioritize by total finding count × UI-file volume; batch 3–6 repos per dispatch round
(parallel agents), never two agents in one repo. A repo that clears every code disappears
from the ratchet at the next regeneration — that is the done-signal.

## Per-repo adoption recipe

Follow the repo's OpenSpec discipline: one change, `openspec validate --strict`, archive
with canonical spec promotion (never `--skip-specs`; the promoted spec needs a real
Purpose — the archiver leaves `TBD`, backfill it), then exactly two commits (impl+tests+
archive+specs, then HANDOFF.md-only) plus one `chore(gate):` commit. `main` only, never
push, never `git add -A`, explicit paths, preserve all foreign uncommitted work.

What the change must deliver:

- **Kit consumption**: vendored `tokens.css` + the app's own properties repointed onto kit
  variables (a mapping/alias layer beats rewriting selectors).
- **Literal drain**: 0 color literals in scope, except declared zones: a `--brand-*` block
  in one stylesheet (chinago pattern), `theme-color` meta (UA chrome can't resolve vars),
  self-contained print/export stylesheets (gradevia `--print-*` block), vendored kit itself.
  Where no kit token matches (openaccounting: slate-200/400), use a marker-delimited
  `--oa-*` bridge block and record a kit-gap debt instead of inventing kit tokens ad hoc.
- **Dark theme, one source of truth**: kit `[data-theme="dark"]` + pre-paint script in the
  HTML head (no flash). No-JS sites: a thin `@media (prefers-color-scheme: dark)` block
  remapping ONLY via `var()` to kit dark primitives (alethefy pattern). A Tailwind
  `dark:` class strategy can be co-driven by the same script (openaccounting pattern).
  A manual toggle may be deferred — record the deferral honestly in the spec.
- **A11y floor**: skip-link → single `<main id="main">`, `lang`, `:focus-visible` ring from
  `--focus-ring`, per-theme `color-scheme`, reduced-motion via kit. Contrast must be
  MEASURED in both themes in a repo-style test (≥4.5 body / ≥3.0 UI), plus a sha-pin drift
  guard and a zero-literal scan. Declaring `contrast_evidence` without a ratio-measuring
  oracle is dishonest — port the kairion `token-conformance.test.ts` pattern.
- **Enforcement**: ui block + bound gate check + sized `timeouts:` (cold builds false-fail
  at the 60s default: 300000ms npm/cargo-native, 120000ms ui-conformance/cheaper stacks).

## Evidence and reporting

Never claim completion without fresh outputs: before/after literal counts,
`ui_conformance.py <repo>` showing `baselined=0` (or the honest shrink number),
build + test totals, `driftwatchdog gate --dry-run` and — where cheap — the real run,
`openspec validate --all --strict` totals. Register anything unfixable this cycle in
`/home/paul/code/gate-debt.json` (repo, check, class, reason, handoff) — that file is the
owner's ledger; agents propose entries, the owning session writes them.
